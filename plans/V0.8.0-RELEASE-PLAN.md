# Plan: the `v0.8.0` release

> Written 2026-10-29 against `0.7.0` (spec `0.23`), from the seven issues on the
> [`0.8.0` milestone](https://github.com/adamkjonsson/python-zipline/milestones).
> Not started.

## The theme: the `0.24` port, and two things a port is the right time for

The `0.7.0` plan closed by warning that
[zipline#166](https://github.com/adamkjonsson/zipline/issues/166) "remains the
thing that would reshape `0.8.0`". It did: spec
[`0.24`](https://github.com/adamkjonsson/zipline/releases/tag/v0.24), *the
sessionizer release*, was tagged on 2026-10-29. It closed #166 and five other
issues, and it took all six findings of our review
([`SPEC-0.24-REVIEW.md`](SPEC-0.24-REVIEW.md), PR #103). So `0.8.0` is a port
first. Five of the seven issues are the port.

The other two are not spec work, and both belong in a release that breaks
anyway:

- **#102, the distribution name.** Renaming what `pip` installs breaks every
  dependency string downstream. Doing it in the release that also moves the
  version gate costs downstream one migration instead of two.
- **#101, the write path's per-record cost.** It is behaviour-preserving, so it
  could ship any time. But #106 adds per-record work to that same path (the
  `copy` checks), so measuring #101 after #106 lands is the only measurement
  that describes what ships.

## The issues

| Issue | What it is | Risk | Why this release |
| --- | --- | --- | --- |
| [#108](https://github.com/adamkjonsson/python-zipline/issues/108) | Port to spec `0.24`: gate, vectors, harness, prose | Low, mechanical | The release |
| [#104](https://github.com/adamkjonsson/python-zipline/issues/104) | A transport extent counts sequence numbers; the FIN's position is owed nothing | **Medium**: moves bytes in every closed TCP stream with a final ACK | Our decode stage's output fails our own `check_coverage` under `0.24` |
| [#105](https://github.com/adamkjonsson/python-zipline/issues/105) | A `message` record may cross its input's seams | Low | `sessionize_stage` cannot write the shape `sessionized-fragments` holds |
| [#107](https://github.com/adamkjonsson/python-zipline/issues/107) | An incomplete reassembly: `undecodable`, and the capture-side trace | Low, docs plus one optional API | Completes #105's lossy case |
| [#106](https://github.com/adamkjonsson/python-zipline/issues/106) | The `copy` flag: token, two write-side `MUST NOT`s, isolation, messages as sent | Medium: new API, and per-record writer state | New in the format |
| [#101](https://github.com/adamkjonsson/python-zipline/issues/101) | ~10 µs per record written, whatever its size | Low if bytes are pinned | Needs #106's checks to be in the path it measures |
| [#102](https://github.com/adamkjonsson/python-zipline/issues/102) | `zpf` on PyPI is someone else's | Low in code, **high in reach** | A break, so it rides the release that breaks anyway |

**Where the port stands before any work** (trial run, recorded on #108): with
only `SPEC_VERSION` bumped and the `v0.24` vectors vendored, all 68 `0.23`
vectors still pass. Among the new ones, 3 tests fail, 5 xfail and 12 already
xpass. Two of the four normative issues (#105, #107) are caught by **no
vector**, so they need tests of our own before they can be called done.

## Decisions for the maintainer

Each has a proposed default, so the work is not blocked on it. Record the
decision and the date here, as the spec's plans do.

- **D1, #102: the distribution name.** Proposed: **`python-zipline`**. It
  matches the repository, and `pypi.org/pypi/python-zipline/json` returns 404
  (checked 2026-10-29). The import name stays `zpf`. Two cautions:
  - A 404 is not a reservation. PyPI also refuses names it judges too similar
    to existing ones, so the name is only safe once registered. Registering it
    is outward-facing, so it is the maintainer's step.
  - `zipline` on PyPI is the unrelated Quantopian backtester, which `CLAUDE.md`
    already notes. `python-zipline` sits next to it in search results. The
    alternative `zipline-payload` (also 404) names the format rather than the
    repository and avoids that confusion.
- **D2, #106: the "messages as sent" affordance.** Proposed: a `copy: bool`
  attribute on `Datagram`, plus `StreamView.datagrams(copies=True)`, where
  `False` skips flagged records. The default keeps what the capture saw, which
  is what `datagrams()` returns today. The spec states both readings, so
  either default is within the standard.
- **D3, #106: the checker's category for a broken `copy`.** Proposed: a
  semantic violation that isolates the session, under a new category
  `copy-mismatch`. That is the spec's licence, and `isolate-copy-differs`
  expects it.
- **D4, #107: a named convenience for the incomplete-reassembly block.**
  Proposed: **yes**, `SessionizeStage.incomplete(cites, *, comment)`, writing
  `reason="undecodable"`. It is two lines over `undecoded()`, and it makes the
  pinned word the default instead of something to remember.
- **D5, #101 item 4: a write-side `check=False`.** **Decided 2026-10-29:
  taken at the end of Phase 6, with its measurements**, not in advance.
  - *Against it:* items 1–3 make the same checks cheaper and write the same
    bytes, but item 4 drops the checks. On the read side, #97's `check=False`
    changes what is *reported* about a file that exists. On the write side it
    would change what is *produced*: the writer refusing a violation before
    writing any bytes is how the library keeps to the standard. #101 leaves
    that design question open, and zpfwire, which filed it, would not want it
    as the default.
  - *For it:* the checker is about 21% of a record's write time at `0.7.0`
    (9.8 µs → 7.7 µs with it stubbed out). Items 1–3 shrink everything else,
    so its share grows afterwards, and Phase 5 adds the `copy` checks to the
    same path.
  - *No deadline:* a keyword-only `check=False` is additive, so any later
    minor can add it. Nothing about `0.8.0` being a breaking release makes it
    cheaper now.

  So: if items 1–3 bring the cost down enough, item 4 is not needed. If the
  checker then dominates, there is a measured case to weigh against the lost
  guarantee.

## Phase 1: #108, the port's mechanical half

Gets to a suite where every remaining failure belongs to a later phase's issue.
The checklist is `docs/dev/contributing.md` § *Porting to a new spec version*.

- [ ] **Re-vendor** `tests/vectors/` from the `v0.24` tag: 77 entries, 89
      files. Do the two sweeps the `0.19` port learned to do:
  - `diff -r` against the tag, excluding `build.py`/`check.py`;
  - project every `.zpf` and compare it to the shipped `.jsonl`.

      `VENDORED.md` → `v0.24`.
- [ ] **Move the gate**: `SPEC_VERSION = (0, 24)`. Then fix the format strings
      in `tests/test_jsonl.py` and anywhere else the suite finds them.
- [ ] **`RecordFlags.COPY = 0x0100` and the `copy` JSONL token**, pulled forward
      from #106. Without it, two JSONL round-trip tests fail outright rather
      than xfail, and the phase cannot end green. Only the bit and the token
      land here; the semantics are Phase 5. The docstring says so until then.
- [ ] **Harness**:
  - `test_every_case_has_a_file` counts 89, with its docstring's breakdown
    updated;
  - **multi-file `merged`** (zipline#163): items carry `file`, the stem
    `files` lists, so the merge test resolves each item against its own member
    file (`chain`, `decoded-past-fin`);
  - pair checks for the new accept fixtures: `check_coverage` and
    `check_splice` on `decoded-past-fin`, `sessionized-fragments`,
    `sessionized-fragment-lost` and `sessionized-across-break`.
- [ ] **Ratchet**: every new name that passes goes into `KNOWN_PASSING` now (12
      at the trial run, more once the harness reads `file`). What still fails
      sits in `UNIMPLEMENTED`, each entry citing its issue. `DEFECTIVE` stays
      empty unless a vector is found wrong, which then goes upstream.
- [ ] **Packaging and prose**: `[project.urls] Specification` names `v0.24`
      (the suite catches this). `README.md`, `CLAUDE.md` ("the standard"
      means 0.24, the 77/89 counts, the paragraph on the port), `docs/index.md`,
      `docs/user/` and `docs/dev/` are grepped for `0.23`. Spec citations that
      say *since `0.23`* stay, because they are history.

**Acceptance:** the suite is green, with xfails only for names in
`UNIMPLEMENTED` that point at #104 or #106.

## Phase 2: #104, the FIN's position

First of the normative phases, because it is the one where this library
currently writes output that its own checker rejects.

- [ ] **One definition of reach.** `StreamView.extent_and_gaps` and
      `stream_extent` (`reassembly.py`): a zero-length placeable record reaches
      its own offset. The memo the `0.7.0` Phase 2 added records the same
      number. Keep it separate from `_sequence_end` in `order.py`, which is
      the merge's *end* and does not change. The spec now draws that line, and
      the code should too, in a comment at each site.
- [ ] **`check_coverage`** (`transform.py`) exempts the FIN's position: the
      data end of a record carrying `fin`, or the offset of a zero-length `fin`
      record, and only inside the extent. A lost FIN followed by a captured ACK
      leaves a position no record marks, which stays an ordinary one-wide hole.
- [ ] **Auto-fill** (`_label_fills` / the ledger's `autofill`, `decode.py`)
      skips the FIN's position, for both stages. Today it would write `skipped`
      there, a bytes-class claim about a position that holds no byte.
- [ ] **Tests**:
  - `decoded-past-fin/decoded` passes;
  - a decode stage over `closed-final-ack` declares 8 and 5, writes no
    Undecoded at `[4,5)`, and `check_coverage` returns `[]` (the repro on
    #104);
  - `merge-pure-ack-and-fin` and `sequenced-pure-ack-and-fin` keep extent 8
    with end 9;
  - a lost-FIN stream still reports its hole.

  Check that each test bites by reverting the fix, as `0.7.0` did.
- [ ] **Changelog *Changed*, observable.** A decode or sessionize stage over a
      closed TCP stream whose final ACK is stored declares an extent one
      larger than `0.7.0` did. This is a byte change in downstream output, and
      Phase 8 measures it.

## Phase 3: #105, the `message` permission

- [ ] `_check_cites` (`sessionize.py`): several cites are allowed with
      `seq_start` **or** `flags & MESSAGE`. Rewrite the refusal message, the
      `FlowSession.record` docstring and the module docstring. Revise the ⚠
      *Stricter than the format* note: its "splitting loses nothing" is false
      for fragments.
- [ ] `check_splice` (`transform.py`): the exemption is `seq_start` or
      `message`, transport layer only, with the docstring updated.
- [ ] **Tests, since no vector covers it:**
  - `sessionize_stage` reproduces the record in `sessionized-fragments/inner.zpf`
    (spans, flags, coverage clean);
  - a `message` record crossing a **declared** break passes `check_splice`;
  - a record with neither kind of evidence is still refused by the stage and
    reported by the check.
- [ ] **Upstream, ask first:** no `v0.24` vector puts a `message` record across a
      declared Discontinuity, which is the half of #105 a harness cannot see. It
      is worth suggesting to zipline as a vector. Filing it is outward-facing,
      so it waits for the maintainer.

## Phase 4: #107, an incomplete reassembly

After Phase 3, because it is that permission's lossy case.

- [ ] Document the rule in `sessionize.py` and `docs/api/sessionize.md`:
      - write no record for the pieces;
      - mark their ranges `undecodable`, with a comment naming the missing
        piece;
      - never leave them to auto-fill, which says `skipped`.

      Include an example on the `sessionized-fragment-lost` shape.
- [ ] D4's `incomplete()` convenience, if decided.
- [ ] Capture-sourced writing: where the docs describe Undecoded against a
      `capture` Source (`undecoded-in-capture`), say that for an incomplete
      reassembly the block is a **MUST** since `0.24`, not optional. This
      library holds no packet reassembler, so the rule lands on producers
      built on `zpf.create`, zpfwire first.
- [ ] Test: `sessionize_stage` reproduces `sessionized-fragment-lost/inner.zpf`,
      with `check_coverage` clean.

## Phase 5: #106, `copy`'s semantics

The bit and token landed in Phase 1. This is the rest.

- [ ] **Writer** (`SessionWriter.record`) refuses `copy`:
  - when the payload differs from the participant's preceding record, or
    there is none;
  - on a participant whose stream carries `seq_start`.

      State per participant is one digest of the last payload, not the
      payload, so a stream of large datagrams costs nothing extra. Test bits
      with `int` arithmetic from the start, which is #101's item 2; there is no
      reason to write the slow form first.
- [ ] **Checker**: the same two rules on transport-layer records, isolating the
      session under D3's category. `isolate-copy-differs` passes. On a
      decoded-layer record the flag is preserved and never checked or
      interpreted, as the spec says.
- [ ] **Reader**: D2's affordance, with docs that name "messages as sent" and
      "what the capture saw" as the spec's two readings, not as the library's
      invention.
- [ ] **Transforms**: `rewrite_decoded` only touches decoded layers, where
      `copy` is opaque, and `merge_files` drops nothing, so neither has a
      predecessor to lose. Confirm both, and say so in their docstrings. The
      spec's "a stage that drops a copy's predecessor clears `copy`" binds a
      transport-layer filter, which this library does not have.
- [ ] **Tests**:
  - `udp-capture-copy` accepts with extent 58;
  - each refusal raises;
  - a triplicate (copy of a copy) is accepted;
  - a decoded record carrying `0x0100` round-trips unchecked.
- [ ] **Watch** [zipline#171](https://github.com/adamkjonsson/zipline/issues/171)
      (what `copy` means on a decoded record). Nothing here depends on it.

## Phase 6: #101, the write path

After Phase 5, so the per-record cost it measures includes the `copy` checks.

- [ ] **Pin the bytes first**: a byte-identity test that writes a fixed
      workload of the issue's shape and compares it with output generated
      before the change. This is what makes items 1–3 safe.
- [ ] **Baseline** with the issue's harness (60,000 records, 64 B and 1,460 B,
      median of three). Record it here before any change.
- [ ] Item 2, integer flag tests in the checker and encoder hot paths. This is
      the cheapest change and is partly done by Phase 5's new code.
- [ ] Item 1, a fixed encoder for the Record's known options in place of the
      generic `_OptSpec` walk.
- [ ] Item 3, skip re-validating a `Record` that `SessionWriter.record` built
      from checked inputs.
- [ ] Measure after each item, and keep the table.
- [ ] **Decide item 4 (D5)** from that table. Record the checker's share of a
      record's write time after items 1–3, with and without the `copy` checks,
      and decide whether a write-side `check=False` is worth losing the
      writer's guarantee. If it goes in, add it as its own step here, with docs
      framed as `#97`'s are: *for output that is checked another way*, not *for
      speed*. If not, say so on #101 with the numbers.

## Phase 7: #102, the distribution name

Late, so that every phase before it installs and tests under the name it
always had. Early enough that Phase 8's downstream review installs the name
that ships.

- [ ] `[project] name` → D1's name. `import zpf` is unchanged.
      `zpf.__version__` reads distribution metadata through
      `_distribution_version("zpf")` (`src/zpf/__init__.py:130`), which
      hardcodes the old name and must change with it. `test_package.py` covers
      this.
- [ ] Recreate the venv's editable install: uninstall `zpf`, then

- [ ] Docs: install instructions, `README.md`, `CLAUDE.md`'s note on the PyPI

- [ ] Changelog **Changed**, at the top of the entry: the install name, and
      the dependency string downstream must use.
- [ ] Registering the name on PyPI is the maintainer's step, if wanted, and is
      outward-facing.

## Phase 8: downstream

The same method as `0.7.0`: throwaway venvs, and **first confirm what each
venv actually imports** (that release's lesson). Run against the `0.8.0.dev0`
build under its new name.

- [ ] **python-zipline-wire.** The issues behind #104 and #105 were filed from
      zpfwire, so this review is the real acceptance test. Expect:
  - extents one larger on every closed TCP stream with a stored final ACK
    (#104);
  - fragmented datagrams that `sessionize_stage` used to refuse (#105);
  - its capture-sourced path now owing the incomplete-reassembly trace, a
    `0.24` **MUST** that is zpfwire's to meet (#107).

  Also measure #101 on its `http_stream_1.pcap` conversion, the issue's own
  benchmark.
- [ ] **zipline-kober.** Its `pyproject.toml` still pins `zpf>=0.6.0,<0.7`, two
      minors behind. Report that rather than assume it.
- [ ] Downstream findings are reported here and **not filed** without being
      asked, as in `0.7.0`.

## Risks

| Risk | Likelihood | Mitigation |
| --- | --- | --- |
| #104 shifts downstream bytes that their tests pin | **High**: it is the intended change | Phase 8 measures it before the tag; the changelog states it as *Changed* |
| A reach/end mix-up: the extent fix leaks into `_sequence_end` and moves merge order | Medium | Separate code paths, a comment at each, and the two `*-pure-ack-and-fin` vectors, whose reach and end differ |
| #101's optimisation moves a byte | Medium | Phase 6 pins bytes before touching the encoder |
| D1's name is refused by PyPI, or taken before registration | Low–medium | Register it before the tag; `zipline-payload` is the fallback |
| zipline#171 lands as `0.25` mid-flight | Low | `0.24` already says `copy` is opaque on decoded records; a port would become Phase 0 of a replan, as `0.6.0` survived |
| #105 and #107 regress unseen, since no vector covers them | Medium | Phase 3's and Phase 4's own tests, and the suggested upstream vector |
