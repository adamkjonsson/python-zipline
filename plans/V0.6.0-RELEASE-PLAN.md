`0.22` closed [zipline#151](https://github.com/adamkjonsson/zipline/issues/151)–[#157](https://github.com/adamkjonsson/zipline/issues/157).

candidate and were fixed before the tag. What the release asks of an
implementation:

| Spec issue | The rule | Work here | Phase |
| --- | --- | --- | --- |
| [#151](https://github.com/adamkjonsson/zipline/issues/151) | Acks unwrap into the peer's offset space, stepping from the previous ack; step 2 compares plain integers | **#75**: the stored-order check and the merge stop comparing serially | 3 |
| [#155](https://github.com/adamkjonsson/zipline/issues/155) | A running maximum of ack *positions* gives the same ordering | None: `_StoredOrder` may keep its running maximum | 3 |
| [#157](https://github.com/adamkjonsson/zipline/issues/157) | Ack positions are **signed**; an unplaceable record still receives edges as `R` | Keep positions signed; don't skip an unplaceable record's ack | 3 |

No block body or option changed, so the codec should not move. Four vectors
are new (`sequenced-past-2gib-pure-ack`, `sequenced-ack-below-origin`,
`sessionized-across-units`, `decap-ethernet`), and the `tunnel` files were
regenerated.

**Measured before planning.** On 2026-10-14 the `0.22` vectors were run in a

- Every existing vector passes, and so do the four new accept vectors' read

ordering code.

## Phase 3: the ack unwrap (#75)

The settled rule (spec §*The guarantee*): a record's `ack` is a **signed**
position in the peer's offset space. Each ack's position is the previous
ack's position plus the signed serial delta of the two values, walking the
acker's records in stored order and skipping records without an `ack`. The
first ack is measured from the peer's origin (`isn + 1`, or the peer's first
captured byte). Step 2 compares the peer record's end (unwrapped offset +
`payload_len`) with the position using plain `<=`.

- [x] `_check_not_already_acked` / `_StoredOrder`
      ([`order.py:344`](../src/zpf/order.py), [`order.py:246`](../src/zpf/order.py)).
      `_max_ack` becomes the running maximum of unwrapped **positions**,
      which #155 confirms is equivalent for ordering. Keep the streaming
      contract: O(1) per participant, no buffering, because the writer's
      linearize guard shares it.
- [x] **The anchor without buffering.** In a mid-stream capture with no
      `isn`, the acker's first ack can be stored before any peer record, so
      the peer's origin isn't known yet. The positions don't need it to be
      known: keep the ack walk relative to the first ack value, and apply
      the constant (the first ack's delta from the origin) once the peer's
      first placed record arrives. `sequenced-ack-below-origin` is exactly
      this shape, with a position of −8.
- [x] **Signed throughout** (#157). An offset is a u64 and an ack position
      is not; a position below 0 acknowledges no captured byte and draws no
      edge.
- [x] **Unplaceable records** (#157). No edge runs *from* one, but its `ack`
      still places it as `R`, so the ack walk must not skip it.
- [x] Reuse `_Placer` (`reassembly.py`) for the signed-delta step, or state
      why the ack walk cannot. **Do not grow a second unwrapping rule.**
      *Done by extracting the step: `_Walk` in `order.py` is the one rule,
      `_Placer` (moved there, since `reassembly.py` imports `order.py` and
      not the reverse) refuses a backward step, and `_AckWalk` takes it.*
- [x] **`_pair_ready` in `causal_merge`** ([`order.py:158`](../src/zpf/order.py))
      makes the same serial ack-vs-end comparison. Move it to positions. The
      harness change in Phase 2 now runs the merge over every unsequenced
      accept vector, so this site finally has coverage.
- [x] The backward-step case (*Caveats*: a retransmission stored ahead of
      2 GiB of peer data) is a producer's duty to omit that `ack`. Nothing
      for the writer API to enforce, since it can't tell a wide retreat from
      a jump. Say so in the docstring.
- [x] Re-run #75's repro verbatim: it writes and verifies clean.
      `sequenced-past-2gib-pure-ack` joins `KNOWN_PASSING`.
- [x] Tell python-zipline-wire **before** the tag: their strict `xfail` for
      #75 becomes an `xpass`.

**Done 2026-10-14**, except the heads-up, which belongs with the release.
`verify_sequenced` and `causal_merge` gained an `isns` keyword; the reader,
the writer and `merge_files` pass their participants'. Four of the new tests
fail on the old code (the #75 repro, a real violation past 2 GiB, the merge
past 2 GiB, and the merge behind an unplaceable peer head); three more pin
rules the old code already met (retreating acks, a negative position, an
unplaceable record's ack). `CLAUDE.md`'s unwrapping trap was rewritten here
rather than in Phase 5, because this phase is what made it wrong.

**Found while testing, not caused by this phase:** step 2 draws an edge from
a zero-length peer record at offset *x* to every record whose ack has reached
*x*. A pure ACK stored after the data it follows, as the specification advises
storing them, therefore points backwards, and the ordinary trace (handshake,
client data, server pure ACK) is refused by `verify()` and stalls the merge,
at `0.5.2` exactly as here. Filed as
[zipline#160](https://github.com/adamkjonsson/zipline/issues/160). It bears on
Phase 4: a sessionizer that covers inner pure-ACK packets with zero-length
records writes files that hit it.

## Phase 4: fan-out sessionization (#76)

The long pole. `0.22` changed two of its premises: #152 lets a
sequence-anchored transport output cross its input's seams, and #154 makes
`tunnel/packets.zpf` real IPv4 + TCP, so `inner.zpf` can be rebuilt from it.

- [x] **Fix the 1:1 path first: transport output must not inherit `units`
      ([#84](https://github.com/adamkjonsson/python-zipline/issues/84)).**
      `decode_stage(..., output_layer=TRANSPORT)` defaults `adjacency` to
      the input's effective value. Over a unit sequence (kober's WireGuard
      output, the input #152 is about), it declares `units` on transport
      participants, and the writer refuses the first record with an
      `AdvisoryError` (*a writer MUST NOT set units there*). Reproduced at
      `0.5.2` with `unit-sequence-nested.zpf` as input. A transport-layer
      stage should default to `contiguous`, and refuse an explicit
      `adjacency=UNITS`. Already wrong at `0.21`.
- [x] **Decide the shape**: a new `sessionize_stage` builder, or a mode of
      `decode_stage`. Two builders over a shared accounting core is likely
      cleaner than one builder with two mapping modes. Make the call and
      record it here.
- [x] **Extract the accounting core** (`_cited`, `_marked`, `_track`,
      `_autofill`, seam handling) so both builders own it. `0.5.2`'s
      phantom-mark fix and `reason_class` keyword come along for free.
- [x] `FileWriter.derive_from` grows a no-mirror mode, or the stage declares
      its `zpf-input` Source directly.
- [x] Output sessions and participants created **on demand** with fresh
      ids, cached per flow key. `record` targets an output session while
      citing an input stream.
- [x] Coverage per **input** stream across **all** output sessions:
      auto-fill takes the union of citations before filling.
- [x] `Session End`: each output session declares the **whole** extent of
      every input stream it cited (`_declare_extents` currently groups by
      matching `session_id`, which is the assumption that breaks).
- [x] **Seams, per #152.** Earlier drafts said an output record must not
      cross an input break. That is now wrong for this stage. A transport
      record that carries `seq_start` **MAY** cite several input units and
      cross an input Discontinuity, and its sequence numbers are the
      stage's assertion that the bytes join. A record **without**
      `seq_start` keeps both duties, and a transport stream still carries
      no Discontinuity. The API needs no `seam=` here; it should refuse a
      multi-span record without `seq_start`.
- [x] **Acceptance, from the issue:** rebuild `tunnel/inner.zpf` from
      `tunnel/packets.zpf` through the new API, parsing the TCP headers in
      the test (the library parses no packets), and match the vendored file
      byte-for-byte, or semantically with a stated reason for any
      block-order difference. Add a second test that coalesces as
      `sessionized-across-units` does. Write to a tmp path; **never write
      into `tests/vectors/`**.
- [x] Docs: a fan-out section in the decode-stage guide, with the
      decrypted-tunnel pipeline as the worked example and `net:ip` as the
      label a generic sessionizer matches. `decode_stage`'s
      `output_layer=TRANSPORT` text says it is the 1:1 case and points at
      the new entry point.

**Done 2026-10-14, except what waits on zipline#160.**

- *Shape:* a separate builder, `zpf.sessionize_stage` → `SessionizeStage`,
  with `FlowSession` per flow, over a core shared with `DecodeStage`: the
  `InputStream` base class and a private `_Ledger` for coverage, both in
  `decode.py`. One builder with two mapping modes would have given every
  `DecodeStage` method a branch it does not need.
- *`derive_from`:* not changed. The stage declares its `zpf-input` Source
  directly, since there is nothing to mirror.
- *Seams:* a record without `seq_start` may cite one range only. That is
  stricter than the format, which allows adjacent ranges where the input
  joins; the docstring says so.
- *Acceptance:* `tests/test_sessionize.py` rebuilds `tunnel/inner.zpf` from
  `tunnel/packets.zpf`, parsing the TCP headers in the test, and the
  projection matches the vendored file block for block, with Source and
  Decoder ids renumbered (this writer numbers from 0, the vector from 1).
- *#84:* fixed as planned; three tests fail without it.

**Waited on zipline#160, settled by `0.23`:** what the stage, and the guide,
say about inner pure-ACK packets. Phase 4c does it.

## Phase 5c: python-zipline-wire's second review (#88–#91)

Four issues, all on `0.6.0`, from reviewing `0.6.0.dev0` + `7bbc44e` while
building python-zipline-wire#35 on `sessionize_stage`. Three are gaps in the
new stage and one is a checker bug; each was checked against the code before
being planned. Two needed a decision, both taken 2026-10-15.

- [x] **[#91](https://github.com/adamkjonsson/python-zipline/issues/91): every
      `FlowSession.end()` re-reads the input** to measure the extents of the
      streams it cited, so ending *n* sessions costs *n* passes over the input.
      Measured downstream: 5.17 s for a conversion that takes 0.16 s from the
      capture, three quarters of it re-measuring two numbers. An outside
      contributor has opened **[PR #92](https://github.com/adamkjonsson/python-zipline/pull/92)**
      against this branch: the ledger caches each input stream's extent and
      gaps by `(session_id, pid)`, and auto-fill shares the measurement. The
      diff was read and is correct and minimal (+12/−2 in `decode.py`, one test
      counting a single measurement over the tunnel's two sessions). *Merged
      2026-10-15 as `3fac9f9`, after a check: 1120 tests pass, a 200-flow
      fan-out over 4000 packets went from 8.65 s to 0.80 s, and the output is
      byte-identical with and without it, for a fan-out and for a
      `decode_stage` with auto-fill.*
- [x] **[#90](https://github.com/adamkjonsson/python-zipline/issues/90):
      `check_splice` reports a crossing the spec permits.** `_crossings`
      reports every record whose citations straddle an input Discontinuity,
      with no layer test, so a sequence-anchored transport record that crosses
      one — which `0.22` (zipline#152) explicitly allows, and
      `sessionize_stage` writes — is reported as a violation. The vector
      `sessionized-across-units` missed it because it crosses `units` seams,
      which `check_splice` does not examine. Fix: skip a record that resolves
      to the transport layer **and** carries `seq_start`, the permission's own
      condition; a transport record without `seq_start` and any decoded record
      keep the duty. Tests: the issue's repro over `tunnel/packets.zpf`, and the
      mirror case still reported. The missing vector (a transport record
      crossing a declared Discontinuity) is upstream's to add: offer to file.
- [x] **[#88](https://github.com/adamkjonsson/python-zipline/issues/88): a key's
      first ended session is its last.** `session(key)` returns the cached
      session even after it has ended, and ignores `session_id=` once the key
      is cached. But the spec's `capture-gap` rule is "end the session at the
      hole and open another *on the same key*", and an idle timeout or port
      reuse does the same. **Decided:** `session(key)` opens a new session
      when the cached one has ended — the issue's first option, so the stage
      follows the format without the caller asking — rather than an explicit
      `new=True`. And:
      `sessions()` lists every session in creation order, an explicit
      `session_id` that disagrees with the key's open session raises rather
      than being ignored, and the test from the issue (two sessions, one key,
      each with its own Session End and the same `input_extents`, coverage
      clean).
- [x] **[#89](https://github.com/adamkjonsson/python-zipline/issues/89):
      neither stage takes `face` or `creator`.** Both reach `create()`, which
      has had both all along, so a stage cannot write the JSON-Lines face and
      names no creator. Additive, with defaults that write what they write
      today. `decode_stage` already carries a `noqa: PLR0913` with its reason,
      so two more keywords cost nothing there, but `sessionize_stage` goes
      from 9 parameters to 11, past `max-args = 10`. **Decided:** the same
      builder suppression, with its reason in a comment as on
      `decode_stage` (approved, as `CLAUDE.md` requires), rather than a bundle
